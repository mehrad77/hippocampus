Agents connect over **MCP**, which gives them tools: remember, recall, ask. On the hosted app, an agent connects with a key or as a connector. On your own machine, `hippo serve` runs the same tools. Either way, an agent's first call is `onboard`, which tells it who it is, and asks a stranger to introduce itself.

## The tools

| Tool | Scope | What it does |
| --- | --- | --- |
| `onboard` | read | Who you are: lane, authority domains, your goals, plus the whole handbook. Call it at the start of a session |
| `recall` | read | Search memory: matching notes with summary and key facts, related notes along the graph, and matching episodes still in the inbox |
| `get` | read | One note in full: every fact with status, provenance, scope and validity; relations; goal state, progress and objectives; guidelines, own and inherited; contact stats; decisions and open questions; open disputes; your notes |
| `neighbors` | read | Walk the relation graph, 1 to 3 steps, optionally one relation type |
| `ask_canon` | read | The canonical answer to a factual question: best-matching facts with status and source, plus any open dispute |
| `briefing` | read | "Previously on…": the chronicle since a date (default a week), recently changed notes, due dates and anniversaries ahead, overdue contacts, open disputes. With `about`, a brief on one person or thing instead (below) |
| `remember` | remember | Queue one episode: `text` (at most 8 KB), plus optional `kind`, `data`, `confidential`, `scope`, `about`, `confidence`, `secret`, `at` |
| `introduce` | remember | Ask to join the party: `title`, `lane`, and optionally `host`, `model`, `about` |
| `update_goal` | goal | Goal status, objectives (`complete`, `reopen`, `add`), progress, due date, owner, counterparty or repeat, applied at once. `update_quest` is its old name and still works |

The curator has five more tools under the `curate` scope; see <Link guide="nightly-sleep">The curator</Link>. Two resources come with the `read` scope: `hippo://handbook` and `hippo://entity/{slug}`. Secrets are never revealed through any of them; see <Link guide="secrets">Secrets</Link>.

Tools outside a connection's scopes are removed, so the client never even sees them. The `goal` scope used to be called `quest`; keys and connectors granted `quest` get `goal`, and new ones carry both names.

A good session follows the server's own instructions. Call `onboard` first. Use `recall`, `get` and `ask_canon` before acting on facts. `remember` anything worth keeping. Treat <code>rumor</code> as "verify first" and <code>disputed</code> as "don't act without checking".

## On the hosted app

Agents connect to your vault's own address, `https://<your-instance>/mcp/<vault id>`, shown on the Setup page. They need a key, or, for Claude.ai and ChatGPT, a GitHub sign-in.

Every connection is to **one vault**. If you have several, each has its own address and its own keys, and a key used at another vault's address is refused. To use two vaults from one app, connect it twice; the snippets name each server after its vault, so they sit side by side.

### Connect an app

On the **Setup** page, for the vault the dashboard shows (switch vaults from the menu at the top of the sidebar), press **Connect an app** and pick the app: Claude Code, Claude Desktop, Cursor, VS Code, Windsurf, Grok (CLI), a Grok bot (xAI API), any other MCP app, or a script. That's the only question. The app gets **one key** (scopes read, remember and goal), and the agents that run in it name themselves.

You get exactly what to paste into that app, with the key already in it, shown **once** (only a hash is stored). The dialog then waits for the app's first call and says when it's **Connected**. Snippets for every other app sit underneath.

```bash
claude mcp add --transport http hippo-vault https://<your-instance>/mcp/<vault id> --header "Authorization: Bearer hippo_…"
```

The **Connected apps** list shows everything connected to the vault, keys and sign-in apps alike: the agents that have spoken through each, what it may do, and when it was last used. **Details** shows the exact kind and scopes; **Disconnect** stops it at once.

One key can carry many agents (a Grok bot with several personalities, Claude Code with several roles): each names itself with the `agent` argument on every call. An agent can't take a name another app or key already uses: the first connection to write as a name holds it. Agents in one app share its key, so to keep one apart, make it a single-agent key through the API.

**Or let the agent connect itself.** An agent that can run commands (Claude Code with the plugin's `/hippocampus:connect`, or any agent that reads `https://<your-instance>/llms.txt`) asks for a code, shows it to you, and you approve it at **/dashboard/connect/**: just which vault. It then picks up its key by itself.

The curator's key is made under **Nightly curation**, not here: see <Link guide="nightly-sleep">the nightly sleep</Link>.

**The Claude Code plugin** brings the server and a skill that teaches an agent how to use memory:

```bash
claude plugin marketplace add mehrad77/hippocampus
claude plugin install hippocampus@hippocampus
export HIPPO_MCP_URL=https://<your-instance>/mcp/<vault id>
export HIPPO_KEY=<the key>
```

Then `/hippocampus:memory` loads the habits: onboard first, read before acting, one memory per call.

### Sign-in apps: Claude.ai, ChatGPT (beta)

Signing in from these apps is still in beta; if it fails, connect another app with a key. In Claude.ai or ChatGPT, add a custom connector with the URL `https://<your-instance>/mcp`. The app asks you to sign in with GitHub, then shows a consent page. The only choice is the **vault** it connects to, if you have more than one. The app can read, remember and update goals, and its agents name themselves on each call (see <Link guide="party-and-lanes">Humans, agents and lanes</Link>); nothing else is asked. (The address `https://<your-instance>/mcp/<vault id>` works too, and starts the page on that vault.)

The **Connected apps** panel on the Setup page lists them, and disconnects any of them.

## On your own machine

### stdio, for local agents

One process per agent, bound to its id with `--agent`:

```bash
claude mcp add hippocampus -- npx -y @mehrad77/hippocampus -v ~/vaults/my-vault serve --agent campus-agent
```

For Claude Desktop, add it to `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "hippocampus": {
      "command": "npx",
      "args": ["-y", "@mehrad77/hippocampus", "-v", "~/vaults/my-vault", "serve", "--agent", "home-finder"]
    }
  }
}
```

To serve a vault on GitHub without a checkout, replace `-v ~/vaults/my-vault` with `--github you/my-vault`, and put a fine-grained token (Contents: read and write, on that repo only) in `HIPPO_GITHUB_TOKEN`.

### Local HTTP, for several agents at once

```bash
npx @mehrad77/hippocampus -v ~/vaults/my-vault serve --http 8765
```

Each agent connects to `http://127.0.0.1:8765/mcp?agent=<id>`, for example:

```bash
claude mcp add --transport http hippocampus "http://127.0.0.1:8765/mcp?agent=job-scout"
```

It listens on 127.0.0.1 only and asks for no key, so any program on this machine can connect as any agent, curator tools included. Use it for agents you run yourself.

### Inbox files, without MCP

A local tool that can't speak MCP may write one new file per memory to `inbox/<its-id>/<YYYY-MM-DDTHHMMSS>-<short-slug>.md`, in the format the handbook shows, and must never touch other files. Everything else should use the tools: they run the checks, and the vault's `AGENTS.md` tells agents not to edit files.

## Which agent is speaking?

- **Hosted app:** a single-agent key's agent, the connector's chosen agent, or the `agent` argument with an agent key.
- **stdio:** `--agent` (or `HIPPO_AGENT`). Without it, the write tools require an `agent` argument.
- **Local HTTP:** `?agent=` in the URL.
- **Inbox files:** the episode's `agent:` property, which must match its folder.

Ids are exact: lowercase letters, digits and dashes, matching `party/<id>.md`. The humans' ids and the reserved ids `human`, `curator`, `unknown` and `hippocampus` are refused. See <Link guide="party-and-lanes">Humans, agents and lanes</Link>.

## New agents introduce themselves

An id with no party sheet still works, but everything it reports counts as a rumor. `onboard` tells such an agent so, and asks it to call `introduce`:

```json
{
  "agent": "job-scout",
  "title": "Job Scout",
  "lane": "Finds paid work in Lisbon and tracks applications. Stays out of housing and the permit.",
  "host": "Claude Desktop",
  "model": "the model it runs on",
  "about": "Searches job boards daily and keeps the job applications goal up to date."
}
```

The introduction waits for you on the **Party** page, and the Tavern lists it under what needs your attention. **Approve** seats the agent with the authority domains you pick; **Dismiss** removes the introduction. Introducing again replaces the earlier one.

## Writing memories the curator gets right

The curator is only as good as what it's given. The handbook gives agents the same advice:

- **One memory per call.** Short, concrete, self-contained.
- **Name things.** People, places and organizations by name, and links in `about` when you know them: `["[[residence-permit]]", "Agência de Migração"]`.
- **Exact values.** ISO dates (`2026-10-14`), amounts with currency (`1,050 EUR`), full IDs, emails and phone numbers.
- **Say how you know** when it matters: "confirmed by email", "seen on the permit portal".
- **Corrections are new memories.** "The appointment moved to…" Never edit old episodes.
- **Pick a kind.** The handbook lists the vault's kinds. Every vault has `observation` (the default), `fact`, `decision`, `task` (something to do, or goal progress), `question` and `interaction` (a call, a meeting, a message); the vault may add its own. An unknown kind is filed as an observation.
- **Mark secrets.** `secret: true` whenever an ID, an account number or a password is involved.
- **Mark what's private.** `confidential: true` for something worth keeping that shouldn't travel: a health detail, a home address. See <Link guide="facts-and-status">Facts and their status</Link>.
- **Say where it holds.** `scope` for a fact that's only true in one context, such as `lang:pt` or `org:harbor-university`.

| Weak | Better |
| --- | --- |
| "Appointment moved." | "The Migration Agency moved the residence-permit appointment to 2026-10-14 10:30 at the Alfama office (confirmed by email)." |
| "Rent is about a thousand." | "The Alfama flat costs 1,050 EUR a month, bills not included (listing seen 2026-09-21)." |
| "Did the language thing." | "Took the HU Language Center placement test today and placed at B1." |

A `remember` call, in full:

```json
{
  "text": "The Migration Agency moved the residence-permit appointment to 2026-10-14 10:30 at the Alfama office. Bring passport, two photos and the signed lease.",
  "kind": "fact",
  "about": ["[[migration-agency]]", "[[residence-permit]]"]
}
```

### Kinds and data

A kind is defined by a note in the vault (see <Link guide="schema-and-presets">Types, kinds and presets</Link>), so `kind` takes any string. The kind decides whether `text` is required, optional, kept only as a gist, or not allowed, and which typed fields go in `data`. An interaction can be pure data:

```json
{
  "kind": "interaction",
  "data": { "with": "[[migration-agency]]", "channel": "call" },
  "text": "Confirmed the documents to bring on 2026-10-14."
}
```

A kind that counts as contact updates the person's or organization's contact stats (`last_contact`), which `briefing` uses to flag overdue contacts and repeating goals use to schedule the next one.

### Briefing on one person

Before contacting someone, call `briefing` with `about`:

```json
{ "about": "[[migration-agency]]" }
```

It returns their canon facts, guidelines for dealing with them, recent interactions, open goals with them, open proposals, and contact stats. Confidential values stay masked unless the connection is bound to an agent with authority there.

<Aside kind="tip">

`remember` returns at once and the episode waits for the next sleep. If the next step depends on it, the agent can still find it: `recall` lists matching inbox episodes under `pending`.

</Aside>
