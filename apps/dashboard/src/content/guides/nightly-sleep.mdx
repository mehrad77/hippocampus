**Sleep** is the curator's shift. It reads the inbox, turns raw episodes into canon, writes the chronicle, opens disputes, and leaves you a morning review. Someone has to do the thinking, and you choose who:

| Curator | Where it runs | Best for |
| --- | --- | --- |
| **Hippocampus itself**, with your own model key | The hosted app, under a monthly cap you set | The hosted app, with nothing of yours to keep on |
| **An agent you trust**, with a curator key | Claude Code, a scheduled task, or GitHub Actions | The hosted app; anyone with a capable agent already |
| **`hippo sleep`** with a model you configure | Your machine, with LM Studio, Ollama or a hosted API | Local vaults, and keeping everything on your machine |

All of them follow the same steps and the same rules, and all commit as *Hippocampus*.

## Step by step

1. **Rulings.** Every open dispute with a `ruling:` becomes canon by you, before anything else.
2. **Batch.** Up to `batch_size` episodes (100 by default), oldest first. The rest wait for the next run, and the Inbox shows them as next, not failed.
3. **For each episode:**
   - **Hints**: names and links in `about` are matched to notes directly, with no model involved.
   - **Mentions**: the curator lists the entities the episode talks about.
   - **Resolve**: each mention is matched by name and alias. Failing that, the curator picks from search candidates or says it's new. New notes are tagged with your domains, or the reporter's lane.
   - **Claims**: the curator extracts facts, relations, goal progress, commitments and guidelines, reusing the field names a note already has.
   - **Reconcile and apply**: deterministic code decides each fact's status (<Link guide="precedence-and-disputes">precedence</Link>), adds relations, updates goals and contact stats, opens proposals for fields only a human sets, and encrypts secrets.
   - **Chronicle**: the episode is appended to `chronicle/YYYY/MM/YYYY-MM-DD.md` as a callout, with the notes it touched and secrets redacted. Then it leaves the inbox.
4. **Summaries.** Each touched note (agent sheets aside) gets its summary paragraph refreshed, if `curator.summaries` is on.
5. **Review and handbook.** `_hippo/review.md` and `HANDBOOK.md` are regenerated.
6. **Audit and commit.** The changes are checked against what the curator may do (never your prose, facts you set, the config, the schema or the agents' sheets, and never a secret or a confidential value in plain text), then committed with a `Hippo-Actor: curator` trailer and the model's name.

<Aside kind="lore" title="Why so many small steps?">

Each step has one narrow job and a strict schema. That's what lets a small local model do this overnight, and it's what lets an agent curate through questions it can answer one at a time. Every answer is checked; one that doesn't fit is sent back with the errors.

</Aside>

## Hippocampus runs it with your key

On a hosted instance that offers it, the app can run sleep itself every night, with your own Anthropic or Mistral API key. Only the vault's owner sets it up, under **Setup & health → Nightly curation**:

1. **The key.** Pick the provider and paste its API key. The app checks it with the provider and seals it. After that you only ever see its last four characters, with **Replace key** to change it.
2. **The models.** **The recommended mix** is the curator eval's pick: for each step, the cheapest model that does it well. Until the eval has been run for a provider, pick **one model for every step**. **Advanced** sets one per step. Each model shows its price, and the card estimates what 100 memories cost at most, with its assumptions beside it.
3. **The caps.** A monthly cap and a per-run cap, in US dollars.
4. **The hour.** Tick **Curate this vault every night** and pick the hour in your own time (it's kept in UTC). **Run now** starts a run at once.

<Aside kind="rule" title="The budget is hard">

Every model call is reserved at the most it could cost before it's made, so no run spends past a cap. At the per-run cap a run stops, and what it finished stays. At the monthly cap curation **pauses** until the next month, or until you raise the cap. A refused key, or a provider out of credit, pauses it until you save a new key. The card says why it paused and what to do, and past runs show each one's cost and why it stopped ("Paused at the budget", "Key refused").

</Aside>

<Aside kind="warn" title="Your provider sees every new memory">

Hosted curation sends every new memory, **secret and confidential ones included**, to the provider you picked, under your key. Members' agents add to the inbox your key pays for: the monthly cap is what bounds it.

</Aside>

### A standby curator

Your own curator agent (below) can stand by in case hosted curation pauses. Schedule it a little after the hosted hour. While hosted curation is on and healthy, and nothing has waited in the inbox for 36 hours, its `sleep_start` answers `not_needed`, and it stops after that one call. When curation pauses, or memories wait too long, it runs as usual. The card shows its last check-in, and the pause banner says whether it will run tonight. The setup prompt asks whether you want one.

## Agent-run sleep

Without hosted curation, the server has no model of its own. An agent you trust does the thinking, through five tools that a **curator key** unlocks:

| Tool | What it does |
| --- | --- |
| `sleep_start` | Opens a run and returns the first questions. One run at a time per vault |
| `sleep_answer` | Sends answers; each is checked against its question's schema |
| `sleep_skip` | Leaves an unclear episode in the inbox for you, with a short reason |
| `sleep_status` | The open run, who holds it, and the last runs |
| `sleep_abort` | Stops the run. What it already committed stays |

Each question carries instructions, an input and a JSON Schema. The agent answers; the server does the bookkeeping and commits each episode as it's done. A run holds a 15-minute lease, renewed by every answer. If the agent stops answering, the run expires on its own, and what's left stays in the inbox. The server's `sleep` prompt holds the whole procedure.

<Aside kind="warn" title="The curator sees everything new">

Curating means reading every new memory in full, **secret ones in plain text**. Whoever holds the curator key, and their model's provider, see them too. Give the key only to an agent you'd trust with your passport number, and never to an everyday agent.

</Aside>

### Setting it up

On the hosted app, **Setup & health → Nightly curation** asks where the curator runs, makes its key, and shows what to run there:

| Where | What it takes |
| --- | --- |
| Hippocampus runs it with your key | Your Anthropic or Mistral API key and a monthly cap (above). Only where the instance offers it |
| One of your agents (recommended) | An agent you already use, such as Claude Code or a Grok bot: its curator connection (one command or tool entry), then a daily task with the sleep prompt. No new charge |
| A script or cron line | Your own machine runs Claude Code (or another agent) every night |
| GitHub Actions | Nothing of yours stays on, but it needs Claude paid for: a subscription token or an API key. Paste it on the card and it goes into the repo's encrypted secrets, with a curator key and the vault's address; then **Turn it on**. GitHub vaults only |

<Aside kind="tip" title="Give sleep a bot of its own">

Make curation a separate agent that only curates (its own Claude Code project or scheduled task, its own Grok bot) with its own curator key, rather than the agent you chat with every day. The curator sees your secrets; keeping it apart keeps them out of everyday conversations, and you can revoke it alone.

</Aside>

In Claude Code, `/hippocampus:sleep-setup` walks you through the same choices and creates the scheduled task. It never asks for the key in the chat: you paste it where it belongs.

### Run it from Claude Code

Mint a curator key under **Setup → Nightly curation** (or let the setup prompt connect a curator by device sign-in). Then install the plugin and connect it with that key:

```bash
claude plugin marketplace add mehrad77/hippocampus
claude plugin install hippocampus@hippocampus
export HIPPO_MCP_URL=https://<your-instance>/mcp
export HIPPO_KEY=<your curator key>
```

In Claude Code, run `/hippocampus:sleep`. Without the plugin, connect the server with the curator key and use its prompt: `/mcp__hippocampus__sleep`.

### On a schedule

Once a day is enough for most vaults; every hour suits agents that write a lot. A run only takes what's in the inbox.

```bash
30 3 * * * HIPPO_MCP_URL=https://<your-instance>/mcp HIPPO_KEY=<your curator key> claude -p "/hippocampus:sleep" --allowedTools "mcp__hippocampus__*"
```

Add it with `crontab -e` on a machine that's on at that hour, with Claude Code signed in and the plugin installed. Scheduled tasks in Claude Code, Claude Desktop or Cursor work as well. Schedule this prompt where the server is connected with the curator key:

> Run the Hippocampus sleep procedure as the vault's curator: call sleep_start with your model name, then answer its questions until the run is done.

### Or let GitHub Actions curate

No machine of your own to schedule on? **Setup → Nightly curation → GitHub Actions** adds a workflow to your vault repo, `.github/workflows/sleep.yml`. It runs Claude every night at 03:23 UTC, through the vault's MCP server with a curator key. It never checks the repo out, and its GitHub token has no permissions.

The card sets the rest up for you, through the GitHub App:

1. Pick how you pay for Claude: a **Claude subscription token** (Pro or Max; run `claude setup-token`; runs count against the subscription, with no API bill) or an **Anthropic API key** (billed per use, so the account needs credit).
2. Paste it, pick the model (Sonnet by default, or Opus) and press **Save to GitHub**. It goes straight into the repo's encrypted Actions secrets; Hippocampus doesn't keep it, and it can't be shown again. Saving one kind deletes the other, so only one is ever set.
3. Saving also makes a curator key for Actions and stores it as a secret. Saving a new token or key makes a new curator key too, and revokes the one it replaces.
4. **Turn it on**, then **Run now** to try it. The workflow file carries the vault's address and the model (neither is secret); picking another model later rewrites it in one commit. **Recent runs** shows the last five, with a link to each on GitHub. A failed run's log ends with why ("Credit balance is too low", say) and nothing else from the run.

The card's checklist shows what's set: the workflow, your token or key, the curator key and the address. If it asks for permission, the app was installed before it could manage Actions: **Approve it on GitHub** opens the installation's settings, where you accept the new permissions.

<Aside kind="tip" title="By hand">
**Set it up by hand** on the card has the `gh` commands. Keys and tokens always go in as **secrets** (`gh secret set`), never variables: a variable is plain text anyone with access to the repo can read, and the workflow doesn't read keys from variables.
</Aside>

| Name | Kind | Value |
| --- | --- | --- |
| `CLAUDE_CODE_OAUTH_TOKEN` | Secret | A token from your Claude subscription. Wins if both are set |
| `ANTHROPIC_API_KEY` | Secret | Or an Anthropic API key |
| `HIPPO_CURATOR_KEY` | Secret | A curator key |
| `HIPPO_MCP_URL` | Variable | Optional: overrides the address written in the workflow |
| `HIPPO_CURATOR_MODEL` | Variable | Optional: overrides the model written in the workflow |

Turning it off on the Setup page removes the file. Turning it on again brings an older copy of the workflow up to date, keeping its model.

### Watching runs

The **curator panel** on the Setup page shows the open run (who holds it, its progress, when its lease ends) and past runs, newest first: finished, expired (the curator stopped answering) or aborted, and for a hosted run, its cost and why it stopped early. You can stop an open run there. Each commit names the curator, its model and the run in its trailers, so the vault's history on GitHub tells you who changed what.

## `hippo sleep` with your own model

For a vault on your machine, `hippo sleep` runs the same steps with a model you configure, and wraps them in git: it pulls first (`git pull --rebase --autostash`), then stages only the paths it changed, never your unrelated edits, commits and pushes.

```bash
HIPPO_LLM_PROVIDER=lmstudio HIPPO_LLM_MODEL=google/gemma-4-26b-a4b-qat npx @mehrad77/hippocampus@0 -v ~/vaults/my-vault sleep
```

With `--github you/my-vault`, pull and push collapse into one commit through the GitHub API, with no clone needed. `hippo serve` also offers the curator tools locally, so an agent can curate a local vault the same way.

### Choosing a model

| Variable | Meaning |
| --- | --- |
| `HIPPO_LLM_PROVIDER` | `lmstudio` (default), `ollama`, `openai-compatible`, `anthropic`, `xai` or `mistral` |
| `HIPPO_LLM_MODEL` | The model id. Each provider has a default, but set it yourself |
| `HIPPO_LLM_BASE_URL` | Server URL. LM Studio defaults to port 1234, Ollama to 11434. Required for `openai-compatible` |
| `HIPPO_LLM_API_KEY` | Or `ANTHROPIC_API_KEY` / `XAI_API_KEY` / `MISTRAL_API_KEY` for hosted providers |
| `HIPPO_LLM_STRUCTURED` | `prompt` (default for local servers) or `native` (default for hosted ones) |
| `HIPPO_LLM_TIMEOUT_MS` | Per-call timeout, default 180000 (3 minutes) |
| `HIPPO_LLM_MAX_TOKENS` | Output cap per call, default 8192 |

Mixture-of-experts models with around 4B active parameters have been a good balance, at roughly one to two minutes per episode. Very long "thinking" models can run into the per-call timeout. Session Zero's Curator step saves these settings, lists the models your local server offers, and tests the connection.

<Aside kind="warn" title="Hosted models see your episodes">

With `anthropic`, `xai`, `mistral` or a hosted OpenAI-compatible API, episode text is sent to that provider, including secrets before they're encrypted. A local model keeps everything on your machine.

</Aside>

### Rehearsals: dry runs

```bash
npx @mehrad77/hippocampus -v ~/vaults/my-vault sleep --dry-run --limit 3
```

`--dry-run` runs the whole curator, models included, and prints what it did, but **writes nothing** and touches no git. It's the safe way to try a new model or a new version. Session Zero can run the same rehearsal from the browser. Other switches: `--limit <n>`, `--no-git` (don't pull, commit or push) and `--no-push` (commit, but don't push).

### Scheduling it

**macOS.** Session Zero's Nightly sleep step installs a launchd job at the hour you pick. Or use the plist in the repo's `ops/` folder and load it with `launchctl`. Make sure your model server is running at that hour.

**Linux and elsewhere.** A cron line works:

```bash
30 3 * * * cd ~/vaults/my-vault && HIPPO_LLM_PROVIDER=ollama HIPPO_LLM_MODEL=<model> npx -y @mehrad77/hippocampus@0 sleep >> /tmp/hippocampus-sleep.log 2>&1
```

Pin the major version (`@0`) wherever you schedule it, so upgrades happen when you choose. Then run `hippo migrate` if the vault format changed. See <Link guide="cli">the command line</Link>.

## House rules

`_hippo/curator.md` in your vault holds your rules for the curator, in plain words: what's worth keeping, when two things are the same, how careful to be with facts, what never goes in a title. Every curator, agent or model, gets them with each step, on top of its built-in rules. Edit them like any note; they apply from the next run.

## Failures stay in the inbox

If anything goes wrong with an episode, such as a timeout, invalid output, an unreachable model, or a curator that skipped it, it **stays in the inbox** for the next run, and the reason is recorded. A sleep never loses a memory. When an episode fails:

- the morning review lists it under "Episodes that failed to consolidate", with its path and the error;
- the dashboard's Satchel and Tavern mark episodes that have already waited through a sleep;
- `hippo sleep` exits with status 2, so a scheduler can notice.

Episodes that didn't fit in this run's batch simply wait their turn.

## The morning review

`_hippo/review.md` is your summary of the night. It records when it ran, which model it used, how many episodes it consolidated, how many failed and how many remain. Then it lists:

| Section | What to do |
| --- | --- |
| ⚖ Disputes awaiting your ruling | Rule in the Council, or write `ruling:` |
| 💡 Proposals | Accept or decline values for fields only you set |
| 🔗 Possible duplicates | Merge the two notes by hand, or decline |
| ❓ Rumors (unverified) | Confirm, correct, or leave for corroboration |
| 🧭 New guidelines | Rules of thumb an agent reported this run; confirm or correct them |
| 🕸 Stale canon | Re-confirm facts older than `stale_after_days` |
| 🧩 Orphan notes | Link them to something, or delete the ones that are noise |
| 📐 Shape notes | Advisory: values that don't fit their field's kind, unknown kinds, and fields in use that their type doesn't declare (candidates for the schema) |
| ✗ Failed episodes | Check the error; they'll be retried |

The dashboard's Home page (the Tavern) shows the same list, live, and adds unknown agents and introductions waiting for you. Five minutes with a coffee is usually enough.

## Things sleep never does

- It never rewrites your prose outside `%% hippo:… %%` regions.
- It never stages your unrelated edits.
- It never decrypts a secret.
- It never deletes an episode it failed to consolidate.
- It never commits a change that fails the audit.
